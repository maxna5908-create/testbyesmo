# Единственная заставка byesmo

Реализация: Kotlin, нативный аппаратно ускоренный `BrandSplashView` (Canvas + один
ValueAnimator) внутри существующего Jetpack Compose приложения. Альтернативные
сплэши, старая анимация системного логотипа, градиент и изображения кнопки удалены.
Иконка приложения не изменена.

## Последовательность

Системный экран — #292D32, прозрачный системный значок; никаких букв до готовности
приложения. PNG и шрифт подготавливаются в Dispatchers.IO. Системный экран снимается
после подготовки ресурсов и первого layout содержимого под заставкой.

Отсчёт начинается после снятия системного экрана:

- 0–300 мс: красное bye растёт из центра, одновременно проявляясь.
- 300–800 мс: bye смещается влево, smo выезжает вправо из-за движущейся маски.
- 800–1450 мс: появляется подпись «выключи тягу курить».
- 1450–1650 мс: неподвижная композиция.
- 1650–1900 мс: вся заставка исчезает над уже подготовленным следующим экраном.

Полное название занимает ровно 60% ширины окна по видимым пикселям, центрировано
по ширине и высоте. Подпись белая, на 12 dp ниже нижней точки логотипа; её реальная
ширина подгоняется к ширине бренда изменением размера шрифта без растяжения.
Тайминги и геометрия: `SplashMotion.kt`.

Системный масштаб длительности анимаций учитывается ValueAnimator; при отключении
анимаций переход происходит сразу. При сворачивании анимация приостанавливается,
при возврате продолжается. При пересоздании Activity заставка не повторяется.

## Исходная графика — без перерисовки

Исходный byesmo_red_white.png: 4096 × 1090, RGBA.
SHA-256 исходного файла:
`01b67d03b255c189eba591ddd5229342cd4538afb6a9c64c4368d89e5072c737`.

Вертикальный разрез x=1914 проходит по полностью прозрачному промежутку между e и s:

- `drawable-nodpi/byesmo_bye_red.png`: исходные x=[0,1914), 1914 × 1090.
- `drawable-nodpi/byesmo_smo_white.png`: исходные x=[1914,4096), 2182 × 1090.

Исходная высота, прозрачность, внешние поля и каждый RGBA-пиксель сохранены.
Соединение по горизонтали попиксельно восстанавливает оригинал. Высокоразрешённые
PNG лежат в приложении; при запуске декодируются один раз с подходящим inSampleSize.
Никакой повторной отрисовки бренда, загрузки из сети, декодирования на каждом кадре,
шейдеров, размытия или пересборки Compose на каждом кадре нет.

## Куда ведёт заставка

В исходном репозитории были только варианты сплэша — ни рабочего экрана, ни входа,
ни слайдов. Добавлен минимальный `LaunchDestination` для проверки перехода:
при первом запуске три ознакомительных шага, затем экран приветствия. Завершение
слайдов сохраняется локально. На следующих запусках открывается приветствие.
Это демонстрационные экраны; авторизация и рабочие функции не имитируются.
При появлении реального маршрутизатора заменить LaunchDestination, сохранив его
предварительную подготовку под заставкой и обработчик завершения анимации.

## Проверка в Android Studio / AI Studio

1. Выполнить pull актуального main, синхронизировать Gradle.
2. Полностью остановить приложение и запустить заново: cold start, не hot reload.
3. Проверить фон без вспышки/дублирующей иконки, порядок bye → smo → подпись → переход.
4. Проверить запуск с очищенными данными и после завершения слайдов.
5. Проверить Android 12+ и Android 7–11, жесты и трёхкнопочную навигацию.
6. Проверить сворачивание во время анимации, поворот экрана, масштаб анимации 0x/1x/2x.
7. Плавность измерять на физических устройствах в release/profile-сборке, включая
   самое слабое поддерживаемое: бюджет кадра ~16,7 мс при 60 Гц, ~8,3 мс при 120 Гц.

Тесты: геометрия и порядок фаз (`ExampleUnitTest`), реальные Canvas-кадры без утечки
белых букв и с последовательной подписью (`SplashRenderingTest`), финальный кадр
той же реализации (`GreetingScreenshotTest`). Снимок генерируется в build/reports.

Для тестов Robolectric с Android SDK 36 нужен **JDK 21**. В репозиторий добавлен
Gradle Wrapper; команды проверки: `./gradlew :app:assembleDebug :app:testDebugUnitTest`
(Windows: `gradlew.bat :app:assembleDebug :app:testDebugUnitTest`).

Проверка 25.09.2026: debug APK собран; 7 unit/Robolectric-тестов прошли.
Кадры 0, 150, 300, 550, 800, 1450 и 1900 мс отрисованы настоящим BrandSplashView;
кадры проверены, исходные PNG дополнительно проверены попиксельной реконструкцией.
FPS на физических устройствах в этом окружении не измерялся.
